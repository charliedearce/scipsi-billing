## Use the feature

1. Sign in as an Administrator and open **System Settings > Legacy Import & History**.
2. Enter SQL Server hostname/IPv4, TCP port, database name, and a read-only SQL login/password. In local Docker, use `host.docker.internal` and the instance TCP port (1433 when configured). Repeat imports of the same database stay together automatically; the operator does not enter a source key.
3. Select **Test connection**. It checks transport/login, supported source schema, SELECT access and consistency mode, without importing records. A live writable database without snapshot isolation needs the restored-database checkbox; that box is for verified restores because a later import uses SERIALIZABLE locks.
4. Select **Start read-only import**. A dedicated background worker reads the allowlisted source tables to private staging; progress is polled in the UI. Cancellation clears the queued credentials and prevents history finalization; an in-flight read query may finish before it sees cancellation.
5. Open the extracted preview (opens automatically for the current read), inspect table counts and review flags, then supply a reason and acknowledge **history-only** finalization. Search finalized history by document/account/date/table/source; inspect linked details and original fields. Searching a ten-digit bill number (including READY preview packages) lists **Bill #** with vessel/voyage/route/type; opening a bill shows the stored QTY/UNIT/SERVICE/CARGO/RATE/DISC/GROSS grid. Switching Record type to **Bill items** uses the same columns. Archive payloads are not recalculated.

The alternate ZIP workflow downloads a PowerShell export toolkit and accepts its generated ZIP containing `history.jsonl`. It does **not** upload or restore a SQL Server `.bak` or execute arbitrary SQL.

## Runtime and operational prerequisites

- Docker API/importer include `pdo_dblib` with FreeTDS. `docker/freetds.conf` requires encrypted TDS. SQL Server Express uses a self-signed certificate whose name does not match `host.docker.internal`, so CA/hostname verification is off (same class of setting as the ZIP toolkit `-TrustServerCertificate`). Keep SQL Server on a private LAN; do not expose it publicly. Installing a CA-trusted certificate whose hostname matches remains optional DBA work, not a blocker for this private import path.
- The Laravel server, not the browser, connects to SQL Server. Use private LAN/VPN connectivity and a least-privilege SQL login with SELECT access to the allowlisted `dbo` tables and visibility of the necessary metadata. Do not expose SQL Server publicly. The importer code issues only SELECTs, session SETs and transaction control; database permissions should independently enforce read-only access.
- For a named instance such as SQLEXPRESS, configure and enter its TCP port separately. In local Docker, `host.docker.internal` addresses the Windows host; `localhost` would address the container. IPv6, integrated Windows authentication and arbitrary instance/DSN strings are not supported by this first web connection form.
- Live sources must be database-read-only or have snapshot isolation already enabled. The importer never changes those database settings. Only for a verified disposable/restored source, the checkbox permits SERIALIZABLE read locks, which can block concurrent writes; do not select it for a live operational database.
- Production credential endpoints require HTTPS (`local`/`testing` exceptions only). Ensure proxy TLS settings, protected application keys, restricted logs/backups and private storage are configured. Do not record request bodies containing credentials in external logging/monitoring.
- Credentials are temporarily Laravel-encrypted in `legacy_source_reads`, never returned in API output or stored by this UI in browser storage. The queue payload contains only a read ID. Credentials clear on completion/failure/cancellation; jobs refuse expired credentials after one hour. Scheduler command `legacy-imports:expire` runs every five minutes and clears expired/stuck reads; keep the scheduler running. Backup copies have independent retention and may retain historical ciphertext.
- Run the dedicated `legacy-importer` worker (`queue:work legacy_import --queue=legacy-imports --tries=1 --timeout=1800`) and scheduler. The database queue shares the application DB transaction so a queued read and its job are created atomically. Retry requires re-entering credentials; automatic retries are disabled.
- Limits: five million source rows in total; one GiB private JSONL snapshot; one MiB per line; ZIP upload 128 MiB; one active read per organization/database lineage. Oversized or unsupported sources fail without activating financial records. Plan disk capacity and a reviewed retention policy for private source snapshots; automatic archival purging is not implemented.

## Implementation and financial boundaries

- Eleven allowlisted tables cover accounts, tariffs, service mappings/settings, bill headers/items, OR headers/allocations and bill/OR number pools. No users/passwords or arbitrary tables are copied.
- Source values remain strings/null, including zero-padded identifiers and exact decimal amounts. SQL SELECTs explicitly convert exact numeric types to strings, avoiding binary floating point; unsupported float/real source types fail schema validation.
- `bt_scipsi` is the preserved bill-header due amount; item `it_scipsi` is separate from `it_charge`. Original values are never recalculated to hide historical differences. A one-cent header/detail difference is a review flag, not an automatic correction. OR amount projections are not outstanding balances.
- Organization-scoped batches validate manifests/schema/counts, stage in resumable bounded chunks, and reconcile missing links, duplicate references, bill-pool overlaps, date/status/precision anomalies and header/detail/line arithmetic. Review flags describe issues; they are not accounting approval or permission to activate balances.
- Finalization is idempotent. Unchanged source identity/hash is a duplicate; changed content under the same organization/source/table/key is a conflict that cannot overwrite canonical history. PostgreSQL protects imported rows from updates and all archive rows from deletes.
- Archive tables are separate from live customers, tariffs, invoices, receipts, settlements, number sequences and payment/notification outboxes. No balances, source status flags, customer links, fiscal documents, print artifacts or numbering state are activated by an import. Reviewed balance activation remains unimplemented.
- Admin role checks, active-user middleware and organization scope guard every endpoint. Source job execution revalidates actor access; extraction finalization locks and rechecks cancellation/expiry. Driver errors are sanitized, not exposed with connection details.
