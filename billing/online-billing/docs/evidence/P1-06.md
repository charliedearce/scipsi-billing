## Implementation and evidence

- Legacy source paths/symbols and confidence: Replaces legacy ad-hoc checkbox flags in VB6 user tables with formal named-permission bundles and strict server-side middleware enforcement.
- Changed paths and resulting behavior:
  - Seeded 33 granular permissions across Identity, Configuration, Audit, Organization, Billing, Receivables, Payments, PPA, Customer, Credit, Documents, and Reports categories.
  - Defined 4 base system roles (`Administrator`, `Teller`, `PPA user`, `Customer`):
    - `Administrator`: Superuser with all system and management permissions including `credit:manage` and `audit:export`.
    - `Teller`: Billing encoder and cashier with `billing:read/draft/post`, `receipts:read/post`, `credit:monitor`, `document_history:view`, and `corrections:request`. Lacks `credit:manage` or user creation.
    - `PPA user`: Philippine Ports Authority officer with cargo clearance verification scope (`ppa:verify`), `document_history:view`, `document_history:compare`, and read-only access. Strictly forbidden from draft billing, credit management, or user administration.
    - `Customer`: Customer portal user with `customer:portal`, `billing:read_own`, `receipts:read_own`, and `proofs:upload`. Strictly forbidden from internal staff endpoints or monitoring other customer balances.
  - Added negative API tests proving privilege boundary enforcement across endpoints.
