# P2-04 Evidence — Integrate Issuance and Artifacts

Date: 2026-09-19. Status: AUTOMATED_VERIFIED.

## Task Summary

Implemented and verified end-to-end integration between invoice posting, deterministic document route selection, server-authoritative canonical PDF artifact generation, immutable historical reprint integrity, and print attempt audit logging per Phase 2 specifications ([Decisions W08, W28, W35](../discovery/DOCUMENT_STUDIO.md), [`PRINT_INVENTORY.md`](../discovery/PRINT_INVENTORY.md), and [`BIR_COMPLIANCE.md`](../BIR_COMPLIANCE.md)). Key deliverables:

- **Deterministic Route Selection Hierarchy (Decision W28)**:
  - Priority 1: `SERVICE_NSCL` — Triggered when any invoice line contains a cargo code starting with `NSCL` (case-insensitive, trimmed).
  - Priority 2: `PPA` — Triggered when total invoice PPA share amount or any individual line item PPA share amount is greater than `0.00`.
  - Priority 3: `SERVICE` — Default standard sales invoice route.
- **Post-Issuance Hook & Frozen Document Snapshots (`DocumentSnapshot`)**:
  - Automatically invoked upon committing the posting transaction in `InvoicePostingService`.
  - Captures complete, immutable dataset dictionaries: invoice metadata, BIR issuer profile, frozen buyer snapshot, financial totals breakdown (VATable, zero-rated, exempt, VAT amount, PPA share, fuel surcharge, total charge amount), and all line item calculations.
  - Records routing provenance: resolved document kind, resolved template code, version number, renderer version (`dompdf 3.1.6`), and timestamp.
- **Canonical PDF Artifact Generation & Private Storage (`DocumentArtifact`)**:
  - Generates binary PDF using Dompdf 3.1.6 based on the active template version layout and frozen snapshot payload.
  - Stores canonical PDF on private storage (`artifacts/invoices/{org_id}/{invoice_id}/snap_{snapshot_id}.pdf`).
  - Computes and stores SHA-256 integrity checksum and exact file byte size.
- **Immutable Historical Reprint Guarantee**:
  - Subsequent downloads and prints stream the exact stored canonical PDF artifact.
  - Template changes, updates, or retirements never mutate or trigger re-rendering of existing issued invoices.
  - The SHA-256 hash of historical reprints remains strictly identical.
- **Failed-Render Retry Isolation**:
  - Rendering errors never abort or roll back posting; the invoice remains safely `POSTED` with allocated sequential numbers.
  - Artifact is recorded with status `FAILED` and captures the exact render error message.
  - Authorized staff can retry rendering from the frozen snapshot via `POST /api/v1/invoices/{id}/artifacts/{artifactId}/retry` without re-running financial calculations.
- **Print Attempts Logging & Audit Tracking (`PrintAttempt`)**:
  - Every print/reprint request is recorded in `print_attempts`:
    - First print recorded as `ORIGINAL` (`is_reprint = false`).
    - Subsequent prints recorded as `REPRINT` (`is_reprint = true`) with optional reason and user attribution.
  - Generates `INVOICE_PRINTED` audit events in `audit_events`.
- **Tenant & Customer Security Boundary**:
  - Customer portal users without staff permissions are strictly restricted to downloading only their own invoices (verified via 403 Forbidden checks).
- **REST Endpoints & Controllers**:
  - `GET /api/v1/invoices/{id}/artifacts`: List snapshots, artifacts, and print history.
  - `GET /api/v1/invoices/{id}/artifacts/download`: Stream canonical PDF.
  - `POST /api/v1/invoices/{id}/artifacts/print`: Record print attempt and return stream/data.
  - `POST /api/v1/invoices/{id}/artifacts/{artifactId}/retry`: Retry failed artifact render.
