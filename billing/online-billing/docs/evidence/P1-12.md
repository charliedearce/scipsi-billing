# P1-12 Evidence — Establish In-App Announcements

Date: 2026-09-19. Status: AUTOMATED_VERIFIED.

## Task Summary

Implemented durable, organization-scoped in-app announcements for scheduled maintenance windows and critical operational notifications per the approved W34 contract (Decision W34, [`ANNOUNCEMENTS.md`](../discovery/ANNOUNCEMENTS.md)). Key deliverables:

- **Durable Relational Persistence**:
  - `announcements`: header table recording organization tenancy, creator/retirer actors, status (`draft`, `scheduled`, `published`, `expired`, `retired`), current version pointer, and lock version.
  - `announcement_versions`: immutable version records with title, plain-language body, severity (`INFO`, `MAINTENANCE`, `IMPORTANT`, `CRITICAL`), audience type (`all`, `targeted`), effective start/end timestamps, dismissal policy, visible change reason, and SHA-256 content digest.
  - `announcement_audience_roles` & `announcement_audience_locations`: concrete foreign-key junction tables for targeted audience evaluation.
  - `announcement_user_states`: per-user delivery state tracking (`seen_at`, `acknowledged_at`, `dismissed_at`), recording interactions without pre-populating rows.
- **W34 Audience & Isolation Rules**:
  - Default audience is all active authenticated users in the administrator's organization, including users who sign in after publication.
  - Targeted audience: multiple selected roles match with **OR**, multiple selected locations match with **OR**, and when both filters exist, a user must match at least one role **AND** at least one location.
  - Strict tenant isolation: announcements never cross organization boundaries.
- **Content Integrity & Sanitization**:
  - Plain text / safe Markdown subset. Raw HTML, script tags, external URLs, and raw data placeholders are rejected with validation errors.
  - Content hash computed using SHA-256 over title, body, severity, audience type, and effective dates.
  - Published versions are immutable; updates require an explicit `change_reason` and generate a new version number.
  - Retirement requires an authorized `retirement_reason` and immediately ceases active display without deleting interaction history.
- **Zero Financial Side-Effects Boundary**:
  - Announcement viewing, acknowledging, or dismissing cannot modify invoices, collection receipts, queue priority, teller actions, PPA cargo clearance, or financial balances.
- **After-Commit Reverb Wake-Up & Realtime Delivery**:
  - `AnnouncementChangedEvent` broadcasts on private channel `org.{orgId}` as `.announcement.changed` with a minimal payload (`announcement_id`, `version`, `action`, `timestamp`).
  - Broadcast is dispatched only after the database transaction commits (`$afterCommit = true`).
  - Vue clients refetch active announcements via the authenticated API, with graceful polling fallback.
- **UI & App Shell Integration**:
  - `AnnouncementBanner.vue`: Non-intrusive alert banner mounted globally under the header in the authenticated shell. Does not obstruct cashier/teller operations. Supports acknowledge and dismiss actions; critical non-dismissible notices remain visible until retired.
  - `apps/web/src/views/communication/announcements/index.vue`: Admin management workspace for creating drafts, scheduling windows, revising published notices, retiring with reason, and viewing revision history with interaction metrics.
  - Registered in router under `Admin > System > Announcements`.
