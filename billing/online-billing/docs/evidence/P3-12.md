## Implemented boundary

- A committed `payment_group` creates one `PAYMENT_INSTRUCTIONS_ISSUED` event for the portal user who selected the bills. The message contains only a generic selection reference and Manila-local deadline; frozen bank instructions remain in the authenticated portal.
- A teller-rejected regular payment proof creates `PAYMENT_PROOF_REJECTED`, a posted regular payment receipt creates `SETTLEMENT_POSTED`, and a deposited check explicitly marked dishonored creates `CHECK_DISHONORED`. Proof upload/resubmission, teller claim and a cleared-but-not-yet-settled check remain deliberately silent.
- Each committed `invoice_credit_charge` creates a `VIP_CREDIT_ASSIGNED` notification event for the customer portal user who charged that bill. The existing local SMS outbox evaluates the active policy, verified mobile contact and preference, then records a queued or suppressed delivery. A multiple-bill charge intentionally creates one safe, per-bill intent so its existing immutable terms and due date are unambiguous.
- A posted VIP repayment creates one `SETTLEMENT_POSTED` event for the repayment submission, with the collection-receipt number as its safe reference. Repeating the idempotent approval command does not create a second event or receipt.
- A teller proof rejection creates one `VIP_REPAYMENT_REJECTED` event. Its SMS template is generic: it never contains the teller's rejection note, bank reference, proof data or amount.
- An immediately effective held or disabled account profile creates one `VIP_CREDIT_ACCOUNT_HELD` event for the primary active customer portal link, preferring the account owner over another active link. A future-dated profile is deliberately not announced before its effective time.
- A posted collection receipt creates `RECEIPT_ARTIFACT_READY` only after its canonical `DocumentArtifact` is successfully `RENDERED`. It targets the receipt customer's active linked portal user with a verified-contact/policy-governed local intent; the safe template contains the collection-receipt number only. A repeat source-key receipt request can re-evaluate a rendered artifact if the earlier notification path failed, but the `(organization, event key, receipt)` lookup prevents a duplicate event or delivery. A failed artifact remains silent; this change does not add an artifact retry workflow.
- An executed APPROVED `RECEIPT_REVERSAL` (P3-04) creates one `RECEIPT_REVERSED` event for an active linked portal user after settlement restore commits. The safe template uses the receipt number and a generic action label only; execute retry does not duplicate the event or call a provider. Notification failure cannot undo the reversed receipt.
- `VipCreditService` schedules the event/outbox work with `DB::afterCommit` in production. It performs no provider call and catches notification-path failures so delivery state cannot create, undo or alter a credit charge, receipt, allocation, PPA result or fiscal document. The unit-test compatibility path creates the local intent synchronously inside Laravel's test transaction; it is not the production dispatch path.
- Seeded, Admin-manageable contractual templates now also include `RECEIPT_REVERSED` alongside `PAYMENT_PROOF_REJECTED`, `CHECK_DISHONORED`, `VIP_CREDIT_ACCOUNT_HELD`, `VIP_REPAYMENT_REJECTED` and `RECEIPT_ARTIFACT_READY`; the existing `PAYMENT_INSTRUCTIONS_ISSUED`, `VIP_CREDIT_ASSIGNED` and `SETTLEMENT_POSTED` templates are reused. Seeding adds defaults for a development/fresh environment without changing financial schema or data.
- `notification_event_locations` now stores immutable, foreign-key-backed operational location scopes for P3 payment, receipt and VIP events. A Teller lists only delivery state for assigned locations; an unscoped account-level event is Administrator-only rather than organization-wide. The API redacts customer message bodies, hashes, provider identifiers, raw observations and local effect keys unless the viewer also holds `sms_deliveries:view_content`; the Vue dashboard explains the restricted state instead of relying on browser-only hiding.
