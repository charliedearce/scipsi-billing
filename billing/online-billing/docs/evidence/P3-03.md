## Implementation and evidence

- Added `document_correction_requests` and append-only `document_correction_request_events` with restrictive target/actor/revision foreign keys, exactly-one-target and distinct-requester/reviewer checks, and partial unique indexes for active target/action requests.
- Added request, independent decision and stale-target validation. A request freezes the target document revision hash and lock version; approval locks and rechecks the original invoice/receipt and latest immutable revision. A stale target returns a conflict instead of acting on stale facts.
- An issued-unpaid invoice can request `INVOICE_CORRECTION`; an invoice with posted receipt allocation is rejected from that path. A posted receipt can request `RECEIPT_REVERSAL` review. Approval alone creates no replacement document and performs no receipt reversal.
- Linked invoice correction execute (2026-09-22):
  - Migration adds `correction_draft_invoice_id` and `replacement_invoice_id` on `document_correction_requests`.
  - `POST .../start-draft` (`billing:draft`) clones the unpaid original into a DRAFT and stores `correction_draft_invoice_id` (idempotent while draft remains DRAFT); re-validates unpaid / target lock.
  - Draft updates use the existing draft update path; `POST .../execute` with `billing:post` posts the draft as a new SI, writes `document_correction_links` (`correction_type=REPLACEMENT`, source=original), sets the original to `SUPERSEDED` with `superseded_by_invoice_id` (number/PDF/snapshots preserved, not collectible), expires open payment instructions on the original, links the replacement onto the same billing request(s), sets request `EXECUTED`.
  - Portal `/portal/bills` and claim lookup remain `status=POSTED` only, so superseded originals do not appear as payable. Paid start/execute blocked. Self-approve still fails.
- Added scoped endpoints: `GET/POST /api/v1/document-correction-requests` under `corrections:request`, approve/reject under `corrections:approve`, start-draft under `billing:draft`, execute branched by `requested_action` (`billing:post` for invoice correction; `receipts:reverse` for receipt reversal under P3-04).
- Document Corrections UI: APPROVED `INVOICE_CORRECTION` shows Start/Open correction draft (dialog with shipment + billing grid) and Post replacement invoice. Queue unpaid list: Correct bill → create request; Continue correction → open APPROVED request (`open_approved=1`).
