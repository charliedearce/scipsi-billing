## Implementation and evidence

- Legacy source paths/symbols and confidence: Replaces legacy administrative VB6 forms (`frmUser`, `frmOptions`) with modern responsive Vue 3 TypeScript workspace.
- Changed paths and resulting behavior:
  - Configured HTTP client and error handlers to pass through Bearer auth tokens, unwrapping direct REST JSON envelopes and handling 401/409/422 responses cleanly.
  - Implemented typed API clients for users, roles, application settings, and audit logs.
  - Implemented User Management view (`/system/user`): listing with search & status filters, Add/Edit dialog with roles and multi-location assignment, optimistic lock versioning (`lock_version`), user suspension/activation, and immediate session revocation.
  - Implemented Application Settings view (`/system/settings`): displays allowlisted system and location settings, security notice forbidding tariff/financial and deployment secrets, and edit modal with optimistic lock conflict detection.
  - Implemented Audit Logs view (`/system/audit`): chronological log browser with action/entity filters, badge formatting, user attribution, and an Inspect Diff dialog displaying old vs new state json/diffs alongside request metadata (IP address, user-agent).
  - Registered `/system/settings` and `/system/audit` in system routes with localization in `en.json` and `zh.json`.
  - Restricted the UI to English: removed language controls from login/header/settings surfaces, removed the locale preference path, and configured Element Plus/vue-i18n with an English-only runtime.
  - Removed the Art Design Pro demo account selector and hardcoded `Super`/`Admin`/`User` credentials. Login now accepts the real email and password; Laravel derives roles and permissions from the authenticated account and the selector value is never trusted.
  - Fixed customer-registration form visibility: the shared login shell's fixed `650px`/`overflow-hidden` layout was overridden for registration with an auto-height, vertically scrollable shell, so the registration submit button is reachable on shorter screens.
  - Fixed the login response boundary: Laravel authentication endpoints return direct JSON resources (`{ token, user }` and the user object from `/auth/me`), while the template HTTP client previously returned only `response.data.data`. The client now accepts both direct resources and `{ data: ... }` envelopes, allowing the token and user profile to reach the login store and route guard.
  - Fixed paginated response handling: Laravel paginator payloads expose their rows as a top-level `data` array alongside `current_page`, `last_page`, and `total`; the shared HTTP client now preserves that metadata instead of treating the paginator as a generic envelope. User Administration normalizes both direct arrays and paginator payloads, and Audit Logs preserves the same pagination contract.
