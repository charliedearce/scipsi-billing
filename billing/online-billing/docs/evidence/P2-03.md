# P2-03 Evidence — Prove Admin Document Studio and Renderer

Date: 2026-09-19. Status: AUTOMATED_VERIFIED.

## Task Summary

Implemented and verified the **Admin Document Studio** presentation engine, server-authoritative preview and validation, versioned binding schemas, protected fiscal blocks enforcement, immutable publication, and scoped effective activation for sales-invoice and bill layouts per Phase 2 specifications ([Decisions W08, W28](../discovery/DOCUMENT_STUDIO.md), [`PRINT_INVENTORY.md`](../discovery/PRINT_INVENTORY.md), and [`BIR_COMPLIANCE.md`](../BIR_COMPLIANCE.md)). Key deliverables:

- **Renderer Architecture & Evaluation (Decision W08)**:
  - **Selected Approach**: Server-side JSON Layout Schema paired with pure-PHP PDF renderer (`dompdf/dompdf` v3.1.6).
  - **Licensing & Cost**: $0 operating cost, open-source LGPL-2.1/MIT dependencies, eliminating proprietary desktop DevExpress runtime licenses.
  - **Operating Environment**: Fully self-contained inside existing PHP 8.4/8.5 runtimes and Debian/Bookworm Docker containers without requiring headless Chrome or Node-based render sidecars.
  - **Fidelity & Units**: Pure millimeter (`mm`) and point (`pt`) coordinate positioning, support for continuous paper or preprinted forms, multi-page item tables, and repeated headers.
- **Relational Tables & Persistence (`document_templates`, `document_template_versions`, `document_template_activations`, `document_template_assets`)**:
  - `document_templates`: Master catalog specifying `document_kind` (`SERVICE`, `SERVICE_NSCL`, `PPA`, `COLLECTION_RECEIPT`), code, name, description, and system flag.
  - `document_template_versions`: Versioned layout records storing `layout_schema_version`, `layout_definition` (jsonb), `validation_summary` (jsonb), and status (`DRAFT`, `VALIDATED`, `PUBLISHED`, `RETIRED`).
  - `document_template_activations`: Scoped routes mapping template versions to organization, document kind, location, and series with effective timestamp ranges and overlap resolution.
  - `document_template_assets`: Stored branding assets (logos, signatures, watermarks) with SHA-256 hashes and dimensions.
- **JSON Layout Schema & Security Sandboxing (`DocumentLayoutSchema`)**:
  - Canonical specification supporting allowlisted bands (`header`, `details`, `summary`, `footer`) and elements (`static_text`, `bound_text`, `line`, `rectangle`, `table`, `image`, `qrcode`).
  - Strict sandboxing: rejects script tags, javascript protocols, event handlers, and unauthorized styling.
- **Protected Fiscal Blocks Enforcement (`FiscalBlockValidator`)**:
  - Publication strictly requires mandatory BIR components for all Sales Invoice layouts:
    1. Issuer TIN, registered name, address, and BIR Permit / CAS notice.
    2. Customer Buyer Snapshot TIN, registered name, and address.
    3. Formatted Sequential Invoice Number & Date.
    4. Line items table binding services, quantities, rates, and line totals.
    5. VAT breakdown (VATable Sales, VAT-Exempt, Zero-Rated, VAT Amount).
    6. Total Amount Due.
    7. Statutory legal disclaimer ("THIS DOCUMENT IS NOT VALID FOR CLAIM OF INPUT TAX" / BIR notice).
  - Omitting, clipping, zero-sizing, or hiding any fiscal block aborts publication with HTTP 422.
- **Immutable Publication & Draft Forking (`DocumentStudioService`)**:
  - Enforces Decision W28: Published versions are strictly immutable. Any modification attempt on a published version fails. Changes require forking a new draft version.
  - Route resolution hierarchy: resolves active published version matching exact `(location, series)` -> `(location)` -> `(series)` -> `(global default)`.
- **Admin Vue 3 Workspace**:
  - Integrated under `/admin/document-studio`: template catalog, status indicators, JSON layout editor, live fiscal block validator, server-rendered PDF preview drawer, and activation manager.
- **REST Endpoints & Controllers**:
  - `GET /api/v1/admin/document-studio/templates`: List templates.
  - `POST /api/v1/admin/document-studio/templates`: Create template with initial draft.
  - `GET /api/v1/admin/document-studio/templates/{id}`: Template details with versions.
  - `POST /api/v1/admin/document-studio/templates/{id}/versions`: Fork draft version.
  - `PUT /api/v1/admin/document-studio/templates/{id}/versions/{versionId}`: Update draft layout.
  - `POST /api/v1/admin/document-studio/templates/{id}/versions/{versionId}/validate`: Validate layout & fiscal blocks.
  - `POST /api/v1/admin/document-studio/templates/{id}/versions/{versionId}/preview`: Generate PDF preview (binary & base64).
  - `POST /api/v1/admin/document-studio/templates/{id}/versions/{versionId}/publish`: Immutably publish version.
  - `GET /api/v1/admin/document-studio/activations`: List active routes.
  - `POST /api/v1/admin/document-studio/activations`: Activate published version.
