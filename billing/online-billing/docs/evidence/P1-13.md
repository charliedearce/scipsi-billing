## Implementation and evidence

- Legacy source paths/symbols and confidence: Legacy VB6/SQL Server system lacked draft revision history and document correction tracking; overwriting records caused historical state loss. Replaced with append-only immutable revisioning and business audit events.
- Changed paths and resulting behavior:
  - Created migration `2026_09_19_100006_create_document_history_tables.php` defining `document_revisions`, `audit_events`, and `document_correction_links` with foreign keys (`ON DELETE RESTRICT`), compound unique constraints, and jsonb storage.
  - Implemented `DocumentRevision` model with lifecycle hooks preventing `updating` or `deleting` operations (`LogicException`).
  - Implemented `DocumentRevisionService`:
    - Generates monotonic revision numbers and optimistic concurrency lock versions.
    - Computes deterministic canonical JSON string and SHA-256 tamper-evident hash (`snapshot_hash`).
    - Automatically calculates field-level differences (`changed_fields`).
    - Recursively redacts sensitive credentials (passwords, tokens, API keys) from revision snapshots.
    - Implemented `compareRevisions()` returning structured old vs new attribute diffs.
    - Implemented `verifyIntegrity()` verifying SHA-256 recalculation against stored snapshot.
  - Implemented `AuditEvent` and `AuditEventService` capturing business event type, aggregate target, actor permission snapshot, request/correlation IDs, idempotency key, and before/after snapshots.
  - Implemented `DocumentCorrectionLink` capturing explicit links between original documents and adjustments or replacements.
  - Seeded permissions: `document_history:view`, `document_history:compare`, `audit:export`, `corrections:request`, `corrections:approve`, `reversals:approve`.
  - Implemented API controllers and routes for listing revisions, retrieving snapshots, comparing revisions, and searching business audit events.
  - Created TypeScript client `apps/web/src/api/documentRevisions.ts`.
