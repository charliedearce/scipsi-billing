# P4-01 — Accounting periods and controlled backdates

## Implemented slice

- Explicit organization-scoped `accounting_periods` with non-overlapping date ranges and irreversible open-to-closed transition.
- A Teller can request an `INVOICE` or `RECEIPT` prior-date authorization; an independent Administrator decides it with an explicit expiry.
- Invoice and collection-receipt issuance resolve an **open** period in the same transaction. A prior date must consume one approved authorization owned by that issuer, for the exact date/document type/location/period; future dates are rejected.
- Issued headers retain the accounting-period and authorization foreign keys. Requests, approval/rejection, period changes and issuance retain audit facts.
- Admin **Accounting Periods** and Teller/Admin **Backdate Authorization** routes are present. The legacy shared system-date override and day-25 rollover are deliberately not copied as implicit web behavior.
