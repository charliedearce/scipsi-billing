# P2-02 Evidence — Implement Posting and Numbering

Date: 2026-09-19. Status: AUTOMATED_VERIFIED.

## Task Summary

Implemented locked document series allocation, sequential numbering register, and atomic invoice posting per Phase 2 specifications (Decisions W07, W28, W35, [`PRICING_RULES.md`](../discovery/PRICING_RULES.md), [`CALCULATION_FIXTURES.md`](../discovery/CALCULATION_FIXTURES.md), and [`BIR_COMPLIANCE.md`](../BIR_COMPLIANCE.md)). Key deliverables:

- **Relational Tables & Persistence (`document_series`, `document_numbers`, `invoice_outbox`)**:
  - `document_series`: Tenancy-scoped sequential series definition with `document_type` (`SALES_INVOICE`), `series_code`, `prefix`, `current_number`, `start_number`, `end_number`, `padding_length`, and active state.
  - `document_numbers`: Sequential issuance audit trail recording `series_id`, `sequence_number`, formatted `formatted_number` (e.g. `SI-0000000001`), `document_type`, `document_id`, and `issued_by_user_id`. Unique constraints prevent duplicate formatted numbers or duplicate sequence allocation within any series.
  - `invoices` enhancements: Added `series_id`, `posted_at`, `posted_by_user_id`, and frozen legal snapshot attributes (`buyer_snapshot_name`, `buyer_snapshot_tin`, `buyer_snapshot_branch_code`, `buyer_snapshot_address`, `buyer_snapshot_business_style`).
  - `invoice_outbox`: Transactional outbox table (`PENDING`, `DISPATCHED`, `FAILED`) staging invoice publication events inside the same DB transaction as posting.
- **Pessimistic Locking & Sequential Register (`DocumentSeries::allocateNextNumber`)**:
  - Leverages `lockForUpdate()` on `document_series` rows within database transactions to eliminate race conditions under concurrent posting requests.
  - Formats numbers with zero-padded sequences based on series configuration.
  - Enforces strict series range boundaries (`end_number`), rejecting issuance attempts with `ValidationException` when series capacity is exhausted.
- **Atomic Invoice Posting Service (`InvoicePostingService`)**:
  - Re-evaluates P0-06 fiscal readiness: Missing BIR fiscal fields (`is_fiscal_ready = false`) abort posting with HTTP 422 Unprocessable Content.
  - Checks document status: Only `DRAFT` invoices can be posted. Re-posting an already `POSTED` invoice fails with HTTP 422.
  - Optimistic concurrency control: Enforces `expected_version` validation against `invoices.version`, returning HTTP 409 Conflict if modified concurrently.
  - Captures immutable buyer snapshot: Copies active customer buyer profile into invoice columns at the instant of issuance. Subsequent customer buyer profile updates never alter historical posted invoices.
  - Revision history: Automatically records an append-only revision in `document_revisions` (Decision W35) with hash verification.
  - Audit logging & transactional outbox: Records business event in `audit_events` and enqueues payload in `invoice_outbox`.
- **Command Idempotency (`IdempotencyMiddleware`)**:
  - Supports both standard RFC `Idempotency-Key` and `X-Idempotency-Key` headers.
  - Network retries with the same idempotency key return the cached successful response without duplicate sequence increments.
- **REST Endpoints & Controllers**:
  - `POST /api/v1/invoices/drafts/{id}/post`: Atomically post invoice draft, assigning number and freezing snapshots.
  - `GET /api/v1/document-series`: Retrieve active document series for invoice issuing.
