## Implementation and evidence

- Legacy source paths/symbols and confidence: The legacy VB6 codebase had no transactional SMS capability; notices were physically distributed or communicated by counter staff. Implemented a decoupled post-commit outbox pattern with immutable versioned templates, verified contact enforcement, controllable fake provider test double, and SkySMS gateway adapter.
- Changed paths and resulting behavior:
  - Added migration `2026_09_19_100009_create_sms_and_notification_preferences_tables.php` establishing the 10 FK-backed tables required by W31:
    - `customer_contact_points`: Verified customer E.164 mobile contacts with verification state and optimistic lock.
    - `contact_verification_events`: Audit trail for mobile contact verifications.
    - `notification_preference_versions`: Versioned customer opt-in/opt-out preferences across channels.
    - `notification_templates` & `notification_template_versions`: Plain-text versioned templates with approved variable catalogs and URL rejection.
    - `notification_policy_versions`: Event enablement, priority (`normal`/`high`), and quiet-hours policies (21:00-07:00).
    - `notification_events`: Durable, immutable after-commit event snapshots.
    - `notification_deliveries`: Outbox records with SHA-256 rendered body hashes, unique `local_effect_key` deduplication, and lifecycle status tracking.
    - `sms_delivery_attempts`: Individual provider dispatch logs with redacted payloads.
    - `sms_provider_status_observations`: Normalized provider status observations (`pending`, `queued`, `sent`, `failed`).
  - Implemented core domain service layer:
    - `SmsGatewayInterface`: Formal gateway contract defining `send`, `reconcile`, and `getHealth`.
    - `FakeSmsGateway`: Test double with controllable modes (`success`, `failure`, `timeout`, `rate_limit`) and in-memory payload inspection.
    - `SkySmsGateway`: HTTP adapter targeting `POST /api/v1/sms/send` with `X-API-Key` reference, rate limiting, and conservative status normalization (`sent` mapped to provider-reported, never hand-waved as delivered).
    - `SmsTemplateService`: Manages plain-text templates with strict validation: forbids URLs, enforces <=1000 char maximum, warns >160 chars, whitelists approved variables (`org_name`, `recipient_name`, `reference_no`, `queue_ticket`, `action_label`, `date_formatted`, `support_contact`), and supports draft -> preview -> publish -> activate -> retire lifecycle.
    - `SmsDeliveryOrchestrator`: Coordinates after-commit outbox queueing, suppression evaluation (unverified mobile, customer opt-out, quiet hours), SHA-256 immutability verification, unique local effect deduplication, dispatching, timeout handling to `unknown_reconciliation_required`, status reconciliation, and audited resending.
  - Implemented RESTful controllers and registered 15 Sanctum-protected routes:
    - `SmsTemplateController`: List, view version history, create draft, publish, activate, retire, and preview with synthetic data.
    - `SmsPolicyController`: Manage event policies, priority, and quiet hours.
    - `SmsDeliveryController`: Outbox dashboard with masked phone numbers, full attempt inspection, provider reconciliation, and audited resend.
    - `NotificationPreferenceController`: Customer self-management of notification preferences with version incrementation.
  - Seeded 14 new communications permissions across Administrator, Teller (limited outbox view), and Customer (`notification_preferences:manage`). PPA users are blocked from all SMS operations.
  - Seeded 5 initial default templates and policies: `BILLING_REQUEST_QUEUED`, `INVOICE_ARTIFACT_READY`, `PAYMENT_INSTRUCTIONS_ISSUED`, `SETTLEMENT_POSTED`, `VIP_CREDIT_ASSIGNED`.
  - Built frontend client and Admin workspace:
    - `apps/web/src/api/sms.ts` & `apps/web/src/api/preferences.ts`: Typed API client interfaces.
    - `apps/web/src/views/communication/sms/index.vue`: Vue 3 + TypeScript workspace featuring Provider Health tab, Templates & Policies tab, Delivery Outbox Dashboard tab with attempt inspection, and Contact Governance tab.
    - Added Transactional SMS route to `apps/web/src/router/modules/system.ts`.
  - Added 19 comprehensive automated tests across 5 test classes in `apps/api/tests/Feature/Sms/`.
