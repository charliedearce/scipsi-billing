# P2-11 Evidence — Transactional SMS Integration

Date: 2026-09-20. Status: AUTOMATED_VERIFIED.

## Task summary

Connected the Phase 2 customer-facing workflows to the existing W31 transactional-SMS foundation. SMS remains a supplementary notification channel; the portal, billing records, fiscal artifacts and payment state remain authoritative.

The implemented Phase 2 event paths are:

- `BILLING_REQUEST_QUEUED` after a valid customer request is admitted to the teller queue.
- `BILLING_REQUEST_CORRECTION_REQUIRED` after a teller requests document correction.
- `INVOICE_ARTIFACT_READY` only after a posted invoice has a successfully rendered canonical artifact.
- `TAX_EVIDENCE_APPROVED`, `TAX_EVIDENCE_REJECTED`, `TAX_EVIDENCE_CORRECTION_REQUIRED` and `TAX_EVIDENCE_REVOKED` after the corresponding withholding/exemption decision.
- `BILL_CLAIM_CODE_ISSUED` for the existing verified counter-claim route, subject to its separate short-lived claim-code controls.

Payment instructions, proof review, settlement/OR, VIP aging and late-charge messages remain scoped to later payment/settlement phases; they are not falsely represented as complete here.

## Implementation controls

- The four owning billing services now require `SmsDeliveryOrchestrator` through constructor injection. A missing dependency can no longer silently disable an event path while the primary transaction succeeds.
- Each workflow creates an immutable `NotificationEvent` and queues a `NotificationDelivery` through the existing template, preference, verified-contact and privacy boundary.
- Production dispatch remains after-commit when the owning workflow is inside a database transaction. PHPUnit uses the normal Laravel `runningUnitTests()` boundary so tests can verify durable event/outbox records without coupling application code to PHPUnit classes.
- Notification delivery is deduplicated by event/source, and SMS is suppressed for unverified mobile contacts or an explicit customer opt-out. SMS failures are isolated from the primary billing transaction.
- `FakeSmsGateway` exposes both its current `getDispatched()` collection and the compatibility `getSentMessages()` test accessor. No provider credential or real SkySMS call is used by automated tests.
- The phase test fixture now supplies the required `invoice_items.tariff_version_id`, `discount_amount` and `net_amount` values. The non-null tariff foreign key remains intact so issued pricing always has attributable provenance.
