## Implementation and evidence

- Legacy source paths/symbols and confidence: The legacy VB6 billing application possessed no realtime WebSocket capabilities or digital messaging; notifications were manual paper printing or face-to-face counter communication. Replaced with Laravel Reverb WebSockets, PostgreSQL durable persistence, and Vue 3 Echo client integration.
- Changed paths and resulting behavior:
  - Installed `laravel/reverb` package (v1.11.1) and configured `config/broadcasting.php` and `config/reverb.php` with Reverb driver defaults.
  - Added migration `2026_09_19_100008_create_conversations_and_notifications_tables.php` establishing:
    - `conversations`: Tenanted threads linked to organization, customer, and optional context (billing request, payment group).
    - `conversation_participants`: Participant tracking with monotonic `last_read_message_id` and timestamps.
    - `chat_messages`: Role-segregated messages with `customer`, `staff_note`, and `system` message types.
    - `in_app_notifications`: Durable user notifications with UUID deduplication (`event_id`) and read states.
  - Implemented after-commit broadcast events with `public bool $afterCommit = true`:
    - `NewChatMessageEvent`: Broadcasts customer messages on `private-conversation.{id}`, and internal staff notes strictly on `private-conversation.{id}.staff`.
    - `InAppNotificationEvent`: Broadcasts personal alerts on `private-user.{userId}`.
    - `DataRefreshEvent`: Emits minimal `{ scope, entity, entity_id, action, version }` wake-up signals on `private-org.{orgId}` and `private-scope.{scope}.{orgId}`. Contains zero sensitive data and acts strictly as a trigger for authorized API refetching.
  - Defined private channel authorization in `routes/channels.php` with `sanctum` and `web` guards:
    - `user.{userId}`: Authorizes matching active user.
    - `org.{orgId}`: Authorizes organization members or administrators.
    - `scope.{scope}.{orgId}`: Checks domain permissions (`billing:read`, `receipts:read`, `settings:read`, etc.).
    - `conversation.{conversationId}`: Restricts to participants or permitted staff; PPA users are explicitly denied chat access.
    - `conversation.{conversationId}.staff`: Strictly restricted to users with `conversations:staff_notes` permission.
  - Implemented API endpoints under `/api/v1`:
    - `ConversationController`: List conversations with unread message counts, create thread, fetch messages (with staff note segregation), send message, mark as read, add participant.
    - `NotificationController`: List user notifications (with unread filter), unread count badge endpoint, mark single read, mark all read.
    - `RealtimeController`: Public `/api/v1/realtime/config` endpoint and Sanctum-protected `/api/v1/broadcasting/auth` endpoint.
  - Seeded 6 new communications permissions (`conversations:read`, `conversations:create`, `conversations:send`, `conversations:staff_notes`, `conversations:assign`, `notifications:read`) across Administrator, Teller, and Customer roles. PPA user receives only `notifications:read`.
  - Installed `laravel-echo` (v2.5.0) and `pusher-js` (v8.6.0) in `apps/web`.
  - Built `apps/web/src/utils/echo.ts` with coalesced/debounced data-refresh listeners and automatic polling fallback when WebSockets are unavailable.
  - Built `apps/web/src/views/communication/notifications/index.vue` with unread badge, category filters, instant mark-all-read, and real-time connection status indicator.
